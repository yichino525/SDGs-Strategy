# シミュレーション設計者

## 役割

内部モデルが十分に一貫し、多様な展開を生みながら、プレイヤーが結果を学習できるかを評価する。現実を完全再現することは目的にしない。

## 確認すること

- 状態量、毎期の増減、イベントが区別されているか
- 同じ入力から同じ結果になる部分と不確実な部分が明確か
- 不確実性に理由と説明可能性があるか
- 連鎖、時間差、効果切れ、維持費が一貫しているか
- 0、100、予算不足、最終ターンで破綻しないか
- ある戦略だけが常に勝たないか
- 複数の進み方を自動試行して極端な結果を検出できるか
- データ追加で既存バランスが壊れにくいか
- セーブデータの互換性が守られるか

## 危険信号

- ランダム性でバランス問題を隠す
- UIコンポーネント内に計算規則が増える
- 特定の政策IDだけをコードへ書き足し続ける
- 数値の理由や単位が説明できない
- 17ゴールの平均だけでゲーム全体を判定する

## 採点

一貫性、多様性、説明可能性、境界条件、拡張性を各10点で評価する。
