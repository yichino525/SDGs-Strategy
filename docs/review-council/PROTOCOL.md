# SDGs Strategy 専門家評議会

ゲームの企画、画面、ゲームデータ、実装を複数の専門視点から独立して点検する。レビューは提案であり、仕様変更や実装の承認ではない。

## 呼び出し方

`/expert-review 対象` と依頼する。対象を省略した場合は、現在の未コミット差分を確認する。

必要に応じてモードを指定できる。

- `quick`：ゲームディレクター、経済、民主的統治の3視点
- `ui`：ゲームディレクター、子ども体験、アクセシビリティ・倫理
- `data`：経済、制度・政治、シミュレーション、史実・倫理
- `full`：全6視点。指定がなければこれを使う

## 評議会の進め方

1. 対象、想定プレイヤー、今回変えてよい範囲を確認する。
2. 各専門家へ同じ資料を渡し、他の専門家の結論を見せずに評価する。
3. 指摘には、可能な限りファイル名、データID、画面名などの根拠を付ける。
4. 観察した事実、設計上の推測、価値判断を区別する。
5. 統合役が一致点と対立点を整理する。多数決で対立を消さない。
6. 変更は行わず、最小の検証案を提示する。実装は別途依頼された場合だけ行う。

複数エージェントを利用できる場合は専門家ごとに独立して評価する。利用できない場合も、各専門家の評価を混ぜずに一度書き出してから統合する。

## 共通の優先度

- `P0`：安全、権利侵害、重大な誤情報、ゲームが進行不能
- `P1`：面白さや判断の意味を根本から損なう
- `P2`：理解、バランス、継続意欲を大きく改善できる
- `P3`：磨き込みや将来候補

各指摘には確信度を「高・中・低」で付ける。根拠が足りない場合は断定せず、確認方法を書く。

## 安全と費用

- レビューだけでは外部AI API、デプロイ、GitHub Actionsを起動しない。
- 有料APIを使う常設機能へ変更しない。
- 個人情報、秘密情報、未公開資料をレビュー報告へ転載しない。
- 史実や政策効果を確認するときは、一次資料を優先し、出典と確認日を記録する。
- 政党支持や特定の思想を正解として採点しない。
